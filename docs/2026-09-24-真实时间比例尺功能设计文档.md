# 真实时间比例尺 功能设计文档

- 日期：2026-09-24
- 状态：待用户确认
- 涉及文件：`index.html`（单文件项目，零依赖约束不变）

---

## 1. 背景与目标

「平行历史」当前的时间轴是**文档流驱动**的：内容书写顺序即时间顺序，但各时间段的**纵向长度与真实时间跨度无关**——夏商近千年只占 2 张卡片的高度，晚清 71 年却挤着 8 张卡。

本功能要把中轴刻度、左右分期色带的纵向排布改为**按真实时间距离等比铺开**，让"夏商之间近千年的空白"本身成为视觉信息，同时通过**局部膨胀机制**保证内容密集区（晚清、民国、现代）不被压垮。

### 非目标

- 不改动任何历史内容、卡片文案、史实
- 不引入依赖、构建工具或框架（零依赖是设计决策）
- 不改手机端（≤768px）布局——维持现有文档流单列
- 不做横向错开（甘特图式多层卡片）——纵向空间由膨胀机制解决

## 2. 已确认的关键决策

| 决策点 | 结论 |
|--------|------|
| 比例尺模式 | 全轴统一真实比例（1 年 = k px），**非**分段压缩 |
| 内容放不下怎么办 | 局部膨胀（方案 B）：该区间撑到内容实际高度，轴上标注断轴符号 |
| 膨胀触发条件 | 只在「内容实际高度 > 等比高度」硬溢出时触发，**不**额外加"卡片间最小间距"条件（刻度胶囊自身高度和常规间距计入内容自然高度，属排版必需，非膨胀条件） |
| 相邻刻度过近（如 1911/1919） | 坐标用年（当年 1 月 1 日），刻度文字仍是「1911年」；胶囊重叠由膨胀的最小排布逻辑兜底 |
| 非单一公元年刻度（「1950年代」「2012年至今」） | 新增 `data-date` 属性作为权威坐标；`.year` 文本只管显示 |
| 比例尺原点 | 截断到最早刻度（约前2070），页首不留史前空白 |
| 手机端 | 完全跳过，保持现状 |
| 实现方式 | JS 运行时算坐标、写内联 `absolute` 定位（与现有 `layoutBands()` 同一架构） |
| 色带定位 | 桌面端改由色带自身的 `data-date` 直接计算，不再读刻度 DOM |
| 比例密度 k | 由卡片实际高度反推（自适应），非固定 1px/年 |

## 3. 总体架构：双坐标系统

页面从「单一文档流」变为「比例尺坐标系 + 内容锚点」：

```text
y(元素) = f(该元素所属区间的膨胀后累计高度)
```

- **理想高度**：`ideal(span) = span(年) × k`，其中 k 是比例密度
- **实际高度**：`actual(span) = max(ideal(span), need(span))`，`need` 是该区间内容的自然高度
- 轴上每一点仍然单调递增对应时间，但膨胀区间的"像素/年"高于标称 k

### 3.1 数据来源：`data-date`

```html
<div class="tick" id="t-1911" data-date="1911"><span class="year">1911年</span>…</div>
```

## 4. 布局算法（桌面端 ≥769px）

### 4.1 触发时机

沿用现有 `layoutBands()` 的四个触发点：`load`、`resize`、`document.fonts.ready`、`ResizeObserver` 观察 `.timeline`。原 `layoutBands()` 扩展为 `layoutTimeline()`，内部完成刻度定位 + 内容定位 + 色带定位 + 断轴标注。

### 4.2 Pass 1 · 求比例密度 k（自适应）

1. 收集所有带 `data-date` 的刻度，按时间排序，得到序列 `t₀ … tₙ`；`minDate = t₀.dataDate`（-2070）
2. 测量内容需求。对每对相邻刻度 `(tᵢ, tᵢ₊₁)`：
   - `need(i)` = 两刻度之间所有 `.row` / `.link-note` 的 `offsetHeight` 之和 + 刻度胶囊自身高度（约 28px）× 2 + 最小安全间距 12px
   - 内容归属：以 DOM 书写顺序划分——一个 `.row` 属于它前面最近的 `.tick`
3. `ideal(i) = (tᵢ₊₁.date - tᵢ.date) × k`
4. 约束：对每个区间，`k ≥ need(i) / (tᵢ₊₁.date - tᵢ.date)`
5. `k = max(所有区间的下界)`，同时设下限 `k_min = 0.25px/年`（防止极端窄屏时先秦段被压得没有存在感）

> k 的物理意义：整页高度由**最挤的区间**决定。当前内容下，最挤的是 1898→1911 区间（13 年里 1 条 row）；k 大约由「现代区间 77 年 × 14 张卡」决定，估算 k ≈ 3–4px/年，整页高度 ≈ 1.4 万–1.6 万 px。先秦各千年区间不受此 k 约束（内容远小于等比高度），保持真实空白。

### 4.3 Pass 2 · 写内联定位

- `.timeline` 总高度 `H = k × (axisEnd - minDate)`，`axisEnd = max(最后刻度 date, 当前年份)`，由 JS 写入 `style.height`
- 对每个刻度：`y(tᵢ) = 累计实际高度`——即从 `t₀` 开始逐区间累加 `max(ideal(i), need(i))`，刻度 `tᵢ` 落在区间 `i-1` 的终点上
- 区间内的 `.row` / `.link-note` 在 `[y(tᵢ) + 胶囊高 + 间距, y(tᵢ₊₁) - 间距]` 内**按书写顺序竖向堆叠**（不按各自事件年份微调——卡片描述的是时期而非时点）
- 所有定位元素设 `position:absolute; top:…px`，`.timeline` 保持 `position:relative`
- 膨胀区间（`need(i) > ideal(i)`）在中点插入 `.axis-break` 节点：轴线上显示 `⧗` 符号，`title` 提示"此段为容纳内容已放大比例"

### 4.4 色带定位

```text
top    = y_of_date(band.start)   // 按 4.3 的累计函数求 date→y 映射
height = y_of_date(band.end) - y_of_date(band.start)   （data-end 缺省时到 H）
```

date→y 映射与刻度定位共用同一个累计函数（分段线性：非膨胀段斜率 k，膨胀段斜率 = need/span）。色带横跨膨胀区间时自动被拉伸，无需特殊处理。

### 4.5 胶囊重叠兜底

相邻刻度 `y` 差小于胶囊高（约 28px）时，说明该区间既短又无内容可撑（如 `t-qing`(1640)→`t-gy1`(1765) 之间有内容、不会发生；真正可能发生的是纯刻度相邻）。处理：把后一个刻度下推到 `前刻度y + 28px`，相当于给该区间加一个 `need` 下限——这天然并入了 Pass 1 的 `need(i)`（胶囊高度已计入），无需独立逻辑。

## 5. CSS 与 HTML 变更

### 5.1 新增 CSS

```css
/* 断轴符号：只由 JS 在膨胀区间插入 */
.axis-break{
  position:absolute;left:50%;transform:translateX(-50%);
  font-size:11px;color:#95a5a6;z-index:2;
```

- 28 个 `.tick` 各加 `data-date`（取值见 3.1 表）

## 6. 行为细节与边界情况

### 6.1 手机端（≤768px）

完全跳过：`layoutTimeline()` 检测 `matchMedia('(min-width:769px)')`，不匹配时清除所有内联定位（`style.top=''` 等），页面回到现有文档流单列。`data-date`/`data-start`/`data-end` 属性在手机端不参与任何计算。

### 6.2 禁用 JS / 降级

- 禁 JS：所有元素保持文档流（现状布局），只是没有比例尺。卡片入场动画本来就在禁 JS 时不生效（已知取舍），布局不受影响——**比"卡片全堆在顶部"好的关键**是 CSS 不预设 absolute
- 某刻度缺 `data-date`：该刻度及之后的内容退回文档流位置（跳过整段定位），Console 发 `console.warn`。不静默失败（现有 `if(!from)return;` 的教训）

### 6.3 窗口 resize

`k` 与所有 `y` 重算。卡片 `offsetHeight` 依赖宽度，宽度变化后 need 变化，k 随之自适应——这正是选自适应 k 的原因。

### 6.4 入场动画

IntersectionObserver 逻辑不变。元素被 `position:absolute` 后仍在视口内时正常触发 `isIntersecting`。唯一注意点：`layoutTimeline()` 需在动画初始状态设置**之前或之后均可**，二者无耦合（动画只改 opacity/transform）。

### 6.5 轴尾

最后一个刻度 `t-now`（2012）之后没有内容，轴尾延伸到**当前年份**（`new Date().getFullYear()`），让「2012年至今」这条色带和轴有真实的"至今"长度。此值随年份自然增长，无需维护。

## 7. 视觉效果预期

- **前2070—前221**：约 1849 年 × k(≈3.5) ≈ 6400px 的滚动区间，只含 4 张卡——大片真实空白，直观传达"上古何其漫长"
- **夏商·王朝之始色带**：从 470 年跨度获得约 1600px 高度（现状约 300px），色带内的空白即信息
- **晚清段（1840—1911）**：71 年等比高度仅 ~250px，内容 need 约 1200px → 触发膨胀，轴上出现 1–2 个 ⧗
- **现代段（1949—2026）**：77 年同样膨胀，⧗ 最密集的区域
- 页脚前轴尾自然收尾

## 8. 测试与验收

项目无测试框架，验收按以下清单人工执行：

1. **结构自检**（现有脚本扩展）：校验每个 `.tick` 有合法 `data-date`、每个 `.era-*` 的 `data-start`/`data-end` 数值合法且 start < end
2. **桌面端 1280px**：色带顶端对齐对应刻度中心；「夏商·王朝之始」明显长于「晚清」；膨胀区轴上可见 ⧗；Console 无报错
3. **手机端 375px**：与改动前完全一致（单列、横向色带、左侧轴）
4. **禁 JS**（DevTools → Disable JavaScript）：页面退回文档流，内容全部可读
5. **resize**：拖拽窗口宽度，布局随卡片高度自适应重排，无错位残留
6. **node --check**：JS 语法校验通过

## 9. 风险与取舍

| 风险 | 缓解 |
|---|---|
| 整页高度 ~1.5 万 px，滚动体验变长 | 这是需求的本质代价（真实比例）；先秦空白正是要传达的信息 |
| k 由最挤区间决定 → 先秦空白可能"过长" | k_min 下限 + 可后续调参；如反馈强烈可改为分档比例尺（方案 C，见下） |
| 双 pass 布局计算量（每次 resize 全量重排） | 元素总量 <100 个，offsetHeight 读取批量化，实测无感；ResizeObserver 已有防抖式的天然节流 |
| 禁 JS 时桌面端退回文档流 | CSS 不预设 absolute，回退即现状布局 |
| 未来新增刻度忘了写 `data-date` | 6.2 的 console.warn 兜底 + CONTRIBUTING.md 补充说明 |

## 10. 备选方案（未采纳，留档）

- **方案 A · 桌面溢出**：卡片横向多层错开。改动最大，突破 1200px 版心，放弃
- **方案 C · 分段压缩**：每个区间手动指定视觉密度档位。调参直观，但失去"统一比例尺"的诚实性，且新增区间要手工配档。若方案 B 上线后先秦空白被证明过长，可降级到 C
- **固定 k=1px/年**：不可自适应，不同屏宽下卡片高度不同会溢出或浪费，放弃
