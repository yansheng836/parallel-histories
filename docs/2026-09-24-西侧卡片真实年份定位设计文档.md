## 1. 背景与问题

上线「真实时间比例尺」后，桌面端的中轴刻度、分期色带都按真实年份等比铺开了，但**西侧（西方）卡片的纵向位置仍然完全错位**。

### 1.1 问题现象

「商朝（约前1600—前1046）」与「古希腊黑暗时代→城邦兴起（前1100—前800）」在时间轴上**齐平**。按真实年份，前 1600 应明显在前 1100 之上。

### 1.2 根因

现有 `layoutTimeline()` 的定位算法是：**每个 `.row` 归属到它前面最近的 `.tick`，然后从该刻度的 y 起，把卡片一张张往下堆**（`layoutTimeline()` 的归组与 Pass 2 定位）。

因此卡片的纵向位置是

```text
卡片 y = 所属刻度的 y + 它在该刻度内排第几张
```

**与卡片自己标题里写的年份毫无关系。**

`data-date` 只加在 `.tick` 上，`.era-*` 上只有 `data-start`/`data-end`。**`.row` / `.card` 没有任何年份属性**——西侧卡片的真实年份只存在于给读者看的标题文字里（`（前1100—前800）`），布局代码看不见它。

即：**不是定位算错了，是这些卡片压根没有属于自己的纵向坐标。**

### 1.3 影响范围

问题不是个例，是**系统性偏移**。全部 33 个 `.row` 的左右年份对照（按偏移量降序，下表只列有代表性的行）：

|---|---|---|---|---|

**先秦至中古几乎全部错位**；近代部分（1840 之后）中西本就同期，因此基本对齐（实测 1840 之后的 13 行偏移都 ≤ 6 年）。

> **口径说明**：「刻度年」列取该行的刻度 `data-date`，不是中国侧卡片标题里的年份。二者可能不同——
> 例如「清朝（前期）」挂在 `t-qing` 刻度（1640，英国革命）上，但卡片标题写的是 1644 清军入关；
> 「盛唐转衰」挂在 `t-tang`（618）上，卡片标题写的是 755 安史之乱。本表统一用**刻度年**，
> 因为西侧卡片原本正是跟着「所属刻度」堆叠的，这才是问题症状的准确归属。

### 1.4 目标

让西侧卡片**按自己的真实年份**在中轴上定位，使「左高右低」的落差如实反映中西事件的时间差。

### 非目标

- 不改动任何历史内容、卡片文案、史实
- 不引入依赖、构建工具或框架（零依赖是设计决策）
- 不改手机端（≤768px）布局——维持现有文档流单列
- ~~不改东侧（中国）卡片的定位规则~~（**后续变更，见 §2.3**：中国侧也按自己的年份定位）

## 2. 已确认的关键决策

| 决策点 | 结论 |
|--------|------|
| 承载年份的属性 | `.card.west` 新增 `data-date`，语义与 `.tick` 的 `data-date` 完全一致（十进制年份，公元前为负，模糊年代取约定值） |
| 是否解析标题文本 | **不解析**。与 3.1 解析规则一致：「`data-date` 是唯一权威来源，不做 `.year` 文本解析回退」 |
| 左右配对 | **保持**。仍是一行左右对照的 `.row` 结构，只是西侧卡片的纵向位置改由自己的年份决定 |
| 中轴连接点 | 每张卡片在中轴上有一个 8px 圆点，**两侧圆点都按自身年份滑动**；连线保持 28px 水平短线不变（见 §5） |
| 中国侧 | **也按自己的年份定位**（§2.3 变更）。多数中国侧卡片年份 = 刻度年，视觉不变；仅 10 张偏移 ≤ 137 年的卡片下移 |
| 手机端 | 不动。西侧卡片照常随文档流排列，`data-date` 不参与手机端布局 |

### 2.1 为什么最初设想中国侧不动（后被 §2.3 推翻）

最初担心：刻度的语义是**中国朝代**（`t-shang` = 「前1600年 商朝」），若让中国侧也按 `data-date` 独立定位，会与刻度胶囊错开——刻度胶囊本身就是中国时间的可视锚点，二者必须重合。

这个理由在「多数中国侧卡片年份恰好等于刻度年」时成立，但对**盛唐转衰（755 安史之乱，挂在 t-tang=618 上）**这类卡片不成立——它与西方侧「法兰克王国（800）」的错位（182 年）其实一半来自**中国侧没对齐**。这正是 1.3 表里最难解释的一行。

### 2.3 中国侧也按自己的年份定位（2026-09-24 变更）

用户明确「要把中国侧也按自己的年份定位」。落地规则：

1. **中国侧红色圆点也按自己的年份滑动**，与西侧一致；中轴上所有圆点严格按时间排序。
2. **统一消重叠**：中国侧与西侧卡片放进同一个队列，按年份排序、逐张下推（含 `.link-note` 避让）。
3. **刻度与分期色带不动**：刻度胶囊仍按刻度年（`t-tang`=618），色带仍按 `data-start`/`data-end` 锚定刻度。中国侧卡片只是从刻度「下移」到自己的年份。

实测：33 张中国侧卡片里只有 **10 张**需要移动，最大偏移是盛唐转衰的 **+137 年**；其余 23 张年份 = 刻度年，视觉无变化。

**取值口径**：中国侧年份从卡片标题首个年份解析（`data-date` 不必另加——中国侧标题年份格式统一，且每张卡片标题首个数字就是该事件的通行年份）。这与西侧 `data-date` 手写不同，因为中国侧标题都是「朝代名（起年—止年）」或「事件（年份）」的规整格式。

### 2.2 为什么用 `data-date` 而不是解析标题

标题格式**不统一**，解析器复杂且会静默出错：

- `（约前1600—前1046）` 带「约」
- `（1914.7.28萨拉热窝事件后爆发—1918.11.11）` 带精确日期和描述文字
- `（19世纪40年代）` 纯模糊年代，无起止
- `（春秋前770—前476；战国前475—前221）` 多个区间
- `（前27—公元476西罗马亡）` 混用「公元」前缀

手写 `data-date` 与 `.tick` 的做法一致，规则简单、无歧义。

### 3.1 `.card.west` 的 `data-date`

```html
<div class="card west" data-date="-1100"><i class="node"></i>
  <h3>古希腊黑暗时代→城邦兴起 <span class="y">（前1100—前800）</span></h3>
```

取值原则（延续前置文档 3.1/3.2 的约定）：

1. 有明确起年的取**起年**——卡片标注的是一个时期的开端
2. 模糊年代取**通行约定值**，并在本文档 3.2 表中写明依据
3. 孤立的单年事件取该年——无起止之分

## 4. 算法设计

### 4.1 定位模型

两侧卡片都按自己的年份定位（§2.3 变更后不再区分）：

| 槽位 | 定位依据 | 横向 |
|---|---|---|
| `.card.cn` | **标题首个年份 → `yOfDate()`**（消重叠时下推） | 左半栏（flex 负责） |
| `.card.west` | **`data-date` → `yOfDate()`**（消重叠时下推） | 右半栏（flex 负责） |

`yOfDate()` 是既有函数（`layoutTimeline()` 内），已能把任意年份映射到 y 坐标——**分期色带就是这么定位的**。卡片与色带属同一类对象，不引入新的映射机制。

**单调性校验必须分同一侧**：用同一个 `lastCd` 会把「一行内中国侧晚于西侧」（这正是对照的意义）误判成倒序——这在最初统一处理时真实踩过，console 会冒出几十条假警告。

### 4.2 校验与降级

| 情况 | 行为 |
|---|---|
| `.card.west` 缺合法 `data-date` | `warn` + 该卡片退回所属刻度 |
| `.card.west` 的 `data-date` 违反递增（同一侧） | `warn` + 该卡片退回所属刻度 |
| `.card.cn` 解析不出年份 | **不 warn**，静默退回所属刻度（合法的模糊年代，如「洋务运动（19世纪60—90年代）」） |
| `.tick` 缺合法 `data-date` | 维持现状：`warn` + **中止整页比例尺布局**（见 4.3） |

**降级策略必须与 `.tick` 分开**：`.tick` 缺 `data-date` 是全局致命错误（比例尺骨架没了），故 `return`；单张卡片缺年份只是局部退化，**不能 `return`**——那会让整页退回文档流，代价远大于收益。

### 4.3 为什么卡片不参与「递增校验中止」

现有代码对刻度做严格递增校验，违反即中止。西侧卡片**不做中止**，因为：

1. 卡片年份由人工填写，笔误概率高于刻度（刻度是页面骨架，修改频率低）
2. 单张卡片错序只影响那一张的视觉位置，不影响比例尺坐标系
3. 中止的代价（全页回退文档流）与收益（一张卡片位置错误）严重不成比例

## 5. 中轴连接点与连线

> **本节方案在实现评审时被推翻过一次，此处记录的是最终落地方案。**
> 最初设计的是「卡片不动、画一条斜线连到中轴」，但斜线的长度/角度会随落差剧烈变化
> （几十像素到上千像素），视觉上从中轴附近整齐的横线矩阵变成大角度扇形，反而更难读。
> 用户给出的手绘稿确定了正确形态：**连线保持水平，只有中轴上的连接点按时间滑动**。

### 5.1 现状

CSS 的固定 28px 水平短横线（`.card::after`）：

```css
.card::after{content:"";position:absolute;top:24px;height:2px;width:28px;background:#bdc3c7}
.card.cn::after{right:-28px}
.card.west::after{left:-28px}
```

它**触到中轴只是因为卡片边缘恰好离轴 48px**（`.row` 的 `padding:0 48px`）。

### 5.2 最终形态

给每张卡片在中轴上放一个 8px 圆点（`.axis-node`，中国侧红、西侧蓝），卡片顶边落在圆点下方 `LINK_T`(24px) 处——**正好是 `::after` 的 `top`**，于是那条 28px 短线仍然水平触到圆点：

```text
商朝     ●←── 商朝（前1600）        刻度 = 前1600年
              （西侧卡片下移到自己的年份）
      ●←── 古希腊黑暗时代（前1100）
西周     ●←── 西周（前1046）        刻度 = 前1046年
```

**连线始终水平，不需要任何旋转**；「按时间排序」体现为三个圆点在中轴上的先后位置。

### 5.3 计算

```text
中国侧：nodeY = 所属刻度的卡片位（iy） + LINK_T
西侧：  nodeY = yOfDate(card.dataset.date) + LINK_T
卡片：  style.top = nodeY − LINK_T − 该行偏移 iy
```

`yOfDate()` 是既有的 `date→y` 分段线性映射（色带就是用它的），西侧卡片与色带属同一类对象，不引入新映射机制。

### 5.4 三条实现约束

1. **只写 `top`，不写 `position:absolute`**。`.card` 本身已是 `relative`；改成 absolute 会让它失去 flex 定位而落到容器左缘（表现为「蓝色卡片跑到左边」），宽度与左右分栏也都由 flex 负责。
2. **用 `offsetTop` 口径换算，不用 `getBoundingClientRect()`**。入场动画的初始态是 `translateY(16px)`，rect 会计入这个 transform，导致 16px 的系统性偏移。
3. **必须消重叠**，见 5.5。

### 5.5 消重叠

两种真实遮挡，都要处理：

| 场景 | 例子 | 处理 |
|------|------|------|
| 两张西侧卡片同年 | 「古希腊黑暗时代」与「古希腊城邦·荷马时代」同为前1100 | 按年份排序后逐张下推，`WEST_GAP` 保底间距 |
| 与居中的 `.link-note` 抢位置 | 「十月革命」落在「巴黎和会」联动卡片的纵向区间里 | 让到 `.link-note` 下面 |

关键点：`nodeY` 是**连接点**（卡片内 `top:24px` 处），不是卡片顶边。比对时卡片实际占据 `[nodeY−LINK_T, nodeY−LINK_T+h]`，漏掉这个换算会漏判。**下推后圆点同步下移**，连线仍然水平触轴。

## 6. 边界与退化

| 场景 | 行为 |
|---|---|
| 手机端（≤768px） | `layoutTimeline()` 清除全部内联定位并删除 `.axis-node` 后 return，西侧卡片照常随文档流排列；`.card::after` 在手机端已 `display:none` |
| 禁用 JS | CSS 不预设 `position:absolute`，卡片退回文档流，`data-date` 不生效；`::after` 仍是现有 28px 横线 |
| 西侧卡片与刻度同y（如 `t-yuan` 1271） | 退化为横线，与现状一致 |
| 多张卡片落在同一年份 | 允许（如「古希腊黑暗时代」「古希腊城邦·荷马时代」同为 -1100，中国侧也可能与同事例同年）；统一排序下推避免完全重叠（见 §5.5） |
| 轴尾段（最后一个刻度之后） | 现有逻辑已处理；西侧卡片仍按 `yOfDate()` 定位 |

### 6.1 中轴圆点只属于桌面端

`.axis-node` 由 `layoutTimeline()` 运行时创建，手机端分支会先删除已有的、再 `return`，因此手机端不会残留圆点。禁用 JS 时圆点从未生成，页面回到纯文档流。

## 8. 实施顺序

1. HTML 加 `data-date`（32 张卡）——**唯一需要史料判断的步骤**
2. JS 定位阶段收集西侧年份 + 校验（不中止布局）
3. JS 西侧卡片独立定位 + 中轴圆点
4. JS 消重叠（同年卡片、`.link-note`）
5. 手机端 / 禁 JS 回退验证
6. 文档同步
7. 桌面端 1280px + 手机端 375px 双宽度验证

**验证方式**：本项目无测试框架。用 Python 脚本做结构自检（`data-date` 合法性与单调性），用浏览器在两种宽度下目视核对——重点核对商朝 vs 古希腊黑暗时代应明显错开，且近代对齐部分无回归。

**实测结论（2026-09-24 完成）**：65 个 `.axis-node` 与 65 张卡片的连接线 y 一一对应（集合比对，误差 0）；32 个西侧圆点严格按时间递增；无卡片互相遮挡、无卡片压住 `.link-note`；Console 无任何 `[timeline]` warn。
